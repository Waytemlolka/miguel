# LobbyLens

Показывает **ID лобби Dota 2 в момент «Матч найден»** — до того, как кто-то нажал «Принять», — и сравнивает его у друзей, которые ищут игру по отдельности (не в пати).

Можно просто сверить **6-значный код голосом** («у меня 146 938» — «у меня тоже»), а можно создать группу: приложение само покажет, с кем совпал матч, в маленьком виджете поверх игры.

> ⚠️ Проект экспериментальный. Главный вопрос — пишет ли Dota ID лобби в лог **до** принятия в обычном/рейтинговом подборе. Приложение само это проверяет и показывает (`ID до принятия: ДА/НЕТ`). Результаты тестов присылайте в issues.

## Скачать

**[⬇ LobbyLens.exe](https://github.com/Waytemlolka/miguel/releases/latest/download/LobbyLens.exe)** — один файл, установка и .NET не нужны (Windows 10/11, x64).

Windows может показать «Система Windows защитила ваш компьютер» (файл не подписан): **Подробнее → Выполнить в любом случае**.

## Настройка (один раз)

1. Steam → ПКМ по Dota 2 → **Свойства** → **Параметры запуска** → впиши:
   ```
   -console -condebug
   ```
   Без этого Dota не пишет файл `console.log`, из которого приложение берёт данные.
2. Перезапусти Dota.
3. Для виджета поверх игры: в настройках Dota поставь режим экрана **«Окно без рамки»** (в полноэкранном режиме ни один виджет не виден).

Приложение само находит `…\steamapps\common\dota 2 beta\game\dota\console.log` во всех библиотеках Steam. Если не нашло — кнопка «Выбрать…».

## Как пользоваться

**Без группы (голосом):**
1. Запусти LobbyLens, каждый ищет игру сам.
2. Когда появится «Принять», в окне/виджете будет `Лобби 146 938`.
3. Сверьте последние 6 цифр. Совпали — один матч.

**С группой:**
1. Один нажимает «Создать группу» → «Копировать код» и кидает код друзьям.
2. Остальные вставляют код → «Войти по коду».
3. Сверни окно — сверху по центру экрана останется виджет: `В одном матче с: Вася, Петя (3/4)` или `Неизвестно`.

Состояния:
- **МАТЧ НАЙДЕН — ждёт принятия** + ID → можно сравнивать.
- **Неизвестно** → матч найден, но ID лобби в логе нет (значит, на вашей версии этот способ до принятия не работает).
- **ID до принятия: ДА / НЕТ** — после нажатия «Принять» видно, появился ли ID раньше.

## Как это работает

Dota (с `-condebug`) пишет в `console.log` служебные строки Game Coordinator, например:

```
[SOCache] CGCSOCacheSubscribedJob(owner=<Lobby:26694969711146938>) [in cache]   ← ID лобби
[GCClient] Recv msg 7170 (k_EMsgGCReadyUpStatus), 22 bytes                      ← матч найден / кто-то принял
[GCClient] Send msg 7070 (k_EMsgGCReadyUp), 19 bytes                             ← ты нажал «Принять»
LOBBY STATE RUN: lobby 26694969711146938: ... MatchID 5451564520                 ← подключение к игре
```

LobbyLens только **читает** этот файл. В игру ничего не внедряется, память не читается, трафик не перехватывается.

**Группа** синхронизируется через публичный MQTT-брокер (`broker.emqx.io`, можно сменить в `%APPDATA%\LobbyLens\settings.json`). Своего сервера не нужно. Всё, что уходит в сеть, зашифровано AES-GCM ключом из кода группы; сам ID лобби не отправляется — только HMAC-«отпечаток», одинаковый у тех, кто в одном лобби.

## Эксперимент: работает ли способ в рейтинге

- **«Проверить текущий console.log»** — отчёт по каждому лобби: был ли ID до принятия, совпал ли с `LOBBY STATE RUN`, это подбор (`mm=1`) или кастомка.
- Все события с точным временем пишутся в `%APPDATA%\LobbyLens\sessions\*.jsonl` («Папка с записями»).

Что известно на сейчас: в **кастомных** лобби ID точно появляется до принятия (проверено по публичным логам). Для **подбора Valve** это ещё нужно подтвердить — пришлите отчёт «Проверить текущий console.log» после пары найденных матчей.

## Честно о правилах

Чтение собственного лога безопасно. Но если специально сводить соло-игроков в один рейтинговый матч (перезапуская поиск, пока не совпадёт), Valve может считать это злоупотреблением подбором — за такое уже банили. Используйте на свой риск.

## Сборка из исходников

Нужен .NET 8 SDK.

```
dotnet test tests/LobbyLens.Tests
dotnet publish src/LobbyLens.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o out
```

Каждый push собирает `LobbyLens.exe` в GitHub Actions и публикует релиз.

Структура:
- `src/LobbyLens.Core` — разбор лога, логика лобби, шифрование группы (кроссплатформенно, с тестами).
- `src/LobbyLens.App` — приложение WPF: окно, виджет, синхронизация группы.
- `tests/LobbyLens.Tests` — тесты.
